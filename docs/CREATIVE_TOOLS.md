# Creative applications | Krita, Audacity, LMMS, Blender

This workflow runs the four requested creative applications on a GitHub-hosted Ubuntu runner. The game owner does not need to install them locally.

## First real content pass

This is no longer only an installation smoke test. The current source branch includes two editable first-pass assets for review:

- **Flame Seal Relic**: an original Persian-fantasy item concept. Blender builds the bronze medallion, dark inset, concentric rims, eight studs, and two-part flame emblem; saves an editable .blend scene; and renders a transparent 512 × 512 image.
- **Divslayer Title Theme — Sketch 01**: an original eight-bar LMMS arrangement at 108 BPM. The tracked .mmp project has a lead motif inspired by a Persian/Hijaz-flavoured scale plus a low drone. CI renders it to WAV so it can be reviewed before it is considered for the soundtrack.

Krita receives a two-layer OpenRaster document (.ora): the Blender render is the base layer and a restrained rim-glint finish is the second editable layer. Krita opens that layered document and exports the final PNG. The ORA remains editable in Krita and other OpenRaster-compatible editors.

Audacity opens the generated LMMS WAV in a virtual display as an application-level smoke check. Its GUI is not remotely scripted; the full-file codec/decode checks remain with the established PyAV/FFmpeg tool. A human listening/mastering pass is still required before any sound is approved for the game.

## Artifact contents

The workflow uploads **Divslayer-Creative-Tools-Review** for 14 days:

- flame-seal-relic.blend — editable Blender scene
- flame-seal-relic-blender.png — Blender render
- flame-seal-relic-layered.ora — editable layered art source for Krita, including the rim-highlight layer
- flame-seal-relic-final.png — PNG exported through Krita
- divslayer-title-theme-sketch-01.wav — LMMS render for listening
- logs, tool versions, and creative-tools-report.json

The tracked LMMS source project is creative/lmms/divslayer_title_theme_sketch_01.mmp. The Blender scene is reproducibly generated by tools/creative/blender_smoke_scene.py. The artwork is a candidate concept, not yet imported into the production asset tree. The music is a draft, not yet selected as the shipping soundtrack.

## Guardrails

- All generated files stay in the CI artifact; this workflow does not overwrite existing files under assets/.
- No QA APK is produced for this asset-only review branch. A device APK should be built only after the owner accepts an actual in-game art/audio change.
- The project’s image rights register and audio credits still need real source, authorship, and usage-term evidence. A successful render or decode is not proof of commercial-use permission.
- Audacity's remote named-pipe scripting is intentionally disabled. Its command-line file-open check is sufficient for this first pass; do not expose an automation pipe as a public server endpoint.

## Future source folders

Keep native editable source files in the repository alongside exported game assets:

- creative/krita/ for .kra or .ora layered artwork
- creative/blender/ for .blend scenes, plus the Python source that regenerates them
- creative/lmms/ for .mmp / .mmpz arrangements and stems
- creative/audacity/ for .aup3 sessions and mastering notes

The first source project is kept in creative/lmms/. The Blender scene and Krita OpenRaster document are published as reproducible workflow outputs until an artwork concept is approved for promotion into the game's asset tree.
